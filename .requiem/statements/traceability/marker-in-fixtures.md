A literal marker in a test fixture or code sample is indistinguishable from a real label, so the scanner finds it. Third instance of the same class after README/SPEC prose and requiem's own generated docs. Resolved with a suppression convention in the linter tradition (nolint, noqa): requiem:ignore on a line opts it out, with free text after it recording why. Checked before the label pattern, because 'ignore' is itself a valid slug and would otherwise parse as a reference to a statement named ignore.
